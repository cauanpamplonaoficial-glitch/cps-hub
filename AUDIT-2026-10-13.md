# CPS Hub V2 — auditoria técnica atualizada (13/10/2026)

## O que foi confirmado
- GitHub Actions run #37 concluiu build e deploy com sucesso. Isso confirma compilação e publicação, não testes de navegador.
- O projeto usa Next.js static export em GitHub Pages sob o prefixo /cps-hub.
- O ambiente V2 é um projeto Supabase isolado. O projeto antigo inativo não deve ser alterado.
- Dados de V1 preservados no arquivo: 848 registros; totais operacionais previamente reconciliados incluem 33 produtos, 80 clientes, 3 fornecedores, 116 vendas/itens, 63 compras/itens e 222 movimentações.
- O código contém autenticação Supabase e consultas reais; notas antigas que diziam não existir backend estavam desatualizadas.

## Correções feitas nesta rodada
1. Corrigido o link “Voltar à CPS Store” para respeitar o caminho base do GitHub Pages.
2. Corrigido o campo de venda relacionada em Garantia/Pós-venda: agora consulta vendas, não registros de garantia.
3. Criadas RPCs transacionais para reservas e vendas Apple Royal, validando proprietário/disponibilidade e atualizando status do aparelho na mesma transação.
4. A interface usa essas RPCs em vez de inserir venda/reserva e atualizar o aparelho em chamadas separadas.
5. Adicionado vínculo de reserva à venda, com preenchimento automático dos dados do cliente/aparelho e filtragem de aparelhos elegíveis.
6. Adicionada validação no banco para impedir venda ligada a reserva de outra conta, reserva não ativa ou aparelho diferente do reservado. Migration `202610130009_apple_royal_reservation_sale_guard.sql` aplicada apenas ao Supabase de teste.
7. Adicionada etapa `npx tsc --noEmit` ao workflow antes do build para detectar erros de tipos antes da publicação.
8. Workflow #44 confirmou build e deploy com sucesso; os commits seguintes dispararam novas execuções e precisam ser confirmados na execução mais recente.

## Problemas que ainda não estão resolvidos
- Não há testes automatizados de navegador/end-to-end; login e fluxos precisam de validação manual.
- Não há `package-lock.json` versionado; a instalação ainda não é totalmente reproduzível.
- Apple Royal ainda não oferece edição/exclusão controlada, conciliação financeira completa, fluxo de recebimentos usando `apple_royal_receipts` ou relatórios detalhados.
- O financeiro registra repasses, não transfere dinheiro nem confirma transações bancárias.
- O log de atividade ainda não cobre todas as alterações de todos os módulos.
- A proteção de senha vazada no Supabase Auth foi identificada como desabilitada e ainda requer ajuste manual nas configurações de Auth do projeto de teste.
- Não foi possível realizar teste visual real em navegador nesta auditoria; build verde não prova que cada fluxo funciona no navegador.
- GitHub Pages publica a interface publicamente; somente os dados estão isolados pelo Supabase de teste. Não inserir dados pessoais reais até definir hospedagem privada/autorização de acesso apropriada.

## Segurança e operação
- Nunca colocar service-role key no frontend. A chave publishable é pública por desenho; autorização depende de RLS.
- Movimentos de estoque importados do V1 não devem ser reaplicados ao saldo.
- Não tratar como produção até testar com sessão real, conferir totais e validar backup/restauração.
